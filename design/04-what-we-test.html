00 / Convention

Design decision vs clinical fact

One visual convention runs through this entire prototype so the two can never be confused.

Verified — usable now

Verificeret

Quoted from pandonia.com or the live booking system. Exactly one piece of marker copy on this whole page qualifies: Pandonia's own D-vitamin description.

Placeholder — cannot ship

Afventer klinisk tekst

Afventer klinisk tekstRendered like this everywhere: dotted rule, muted ink, a red mono tag. It states what the sentence will do and how long it will be, so typography can be judged — without a single fabricated claim.

Why not just write plausible copy

Because it would be indistinguishable from approved copy six weeks from now, and someone would ship it. A convincing prototype with invented science is worse than an obviously incomplete one — and on a medical site the incompleteness has to be visible in the design itself, not in a footnote.

A build rule, not a note

The .pl class is a build-blocking convention: the production site should fail its own pre-deploy check if any element carrying it reaches a build. That turns a promise into a mechanism.

The index bar

46px, sticky, cream, two hairlines. Six area names in Degular at 11.5px with the current one underlined in forest, and a filter field on the right using the Phase 2 underline-only input. No pills, no chips, no left rail — the full width stays available for editorial composition.

The marker row

Four columns: name plus a one-line meaning, unit, inclusion state, and a + that rotates to ×. The meaning sits in the serif at 13.5px — it is the only place on the site where the editorial voice appears at body size, and it is what stops the list reading as a spreadsheet.

Inclusion state

Health Test / også enkelttest, in mono, right-aligned, ink-3. Function's included/add-on idea, executed as plain text rather than a badge. It connects the science to the product without a single CTA.

Panels are not markers

"Elektrolytter og væskebalance" is a panel whose contents Pandonia does not publish. The row says so rather than pretending it is one marker with one range — and the design note states that a panel will eventually expand into several marker rows.

Area footer, not header

Layer 2 appears at the end of the area, in mono, under a rule, labelled "Bag dette område". You meet the biology after the markers, as an explanation of what you have just read — not as a second menu before you start.

03 / Mobile

Mobile

Three things are redesigned rather than reflowed: the index, the marker row, and the range column.

The index becomes an overlay

The sticky bar collapses to a single row: OMRÅDER ▾ on the left, a filter glyph on the right. Tapping it opens a full-screen deep-forest overlay with the six areas set in the serif at D3 — the same pattern as the site's main mobile navigation, so it is learned once and reused.

No horizontal chip scrolling. A row of six categories scrolling sideways at 390px hides half of them and is the most common failure on pages like this.

The marker row loses two columns

Unit and inclusion state drop out of the summary row and move into the expanded body. What remains is the name, the one-line meaning, and the +. Scanning beats completeness at 390px; the detail is one tap away and it is the same tap either way.

The range column goes full width

The desktop layout puts the band in a 300px right column beside the definition list. On mobile the band moves above the list, full width, so it is the first thing in the expansion — the most visual element leads.

No horizontal scrolling anywhere

There is no table on this page, by design. The definition list stacks, the bands are full width, and the two-layer relationship rows wrap. The one place a horizontal rule of thumb might tempt us — comparing two sex-specific ranges — is solved by stacking them instead.

Filter opens inline

Tapping the filter glyph expands a full-width underline field directly beneath the bar and pushes content down. It does not open a modal or a separate search screen — the results are the page itself, filtering live.

Area chapters keep their photograph

Recropped from 16:9 to 3:2 and full-bleed. The photograph is what keeps a long marker list from reading as a document, and dropping it on mobile would remove the Dagslys half of the page exactly where it is needed most.

04 / Range

The range component, all states

Phase 2 defined one band assuming every marker has a value and a range. Neither holds. Seven states, all with clearly labelled demonstration numbers.

Every number in this section is invented for layout purposes and says so on the component. None of it is a Pandonia reference range, and none of it should be read as one. The component is a design specification; the data is scaffolding.

01 · Reference only, no value
Markør
0DEMODATA 30–160250

The default state on Hvad vi måler. There is no personal value on this page, so no tick. The band shows only where the reference interval sits on the scale. Phase 2 had no state for this — it is the most-used state on the whole site.

02 · Value inside range
Markør
78enhedInden for området
0DEMODATA250

Neutral. Amber tick, sage band, no green tick, no reassuring message. Being inside the range is not an achievement — the design refuses to congratulate.

03 · Near a boundary
Markør
33enhedInden for området
0DEMODATA250

No special treatment, deliberately. Introducing an amber "borderline" state would put a judgement on a value that is inside the range. The position on the band already says it — the tick is visibly near the edge, and a reader can see that without being told to worry.

04 · Outside range
Markør
18enhedUnder området
0DEMODATA250

Brick tick plus a 1px lead rule to the band edge, so the eye measures how far. No red fill, no icon, no exclamation. Never appears on the homepage — approved Phase 3 rule.

05 · No simple range
Markør
1,4ratioVurderes i sammenhæng
INGEN ENKEL REFERENCE

The state that stops the component lying. Ratios, derived values and markers whose meaning depends on other markers get a bare scale with a tick and no sage band. It says: here is where you sit, and no, there is no universal good or bad here.

06 · Varies by sex or age
Markør
KVINDER 18–50 · DEMODATA
MÆND · DEMODATA

Stacked, never a toggle. A toggle hides the fact that the ranges differ — which is often the most interesting thing on the screen. The reader's own band carries the tick; the other is shown empty for comparison.

07 · Unavailable
Markør
—AFVENTER LABORATORIET—

Diagonal hatch at 7% ink, endpoints as em-dashes, a mono reason. Used throughout this prototype. An empty band is honest; a plausible invented one is not. Also covers a result that could not be analysed.

What the component must never do

Never traffic lights

No red/amber/green triplet. Two clinical states plus position. Colour never carries the judgement alone — the tick's position on the band is the primary signal and the label is secondary.

Never a tick or a cross

No green checkmarks, no warning triangles, no circular scores, no ring. A biomarker is a typeset scientific object, not a fitness widget.

Never imply one universal scale

State 05 exists because some markers genuinely cannot be read as good/bad. If the component cannot express that, it will quietly teach the wrong idea across thirty-four markers.

Never render a range it does not have

State 07 is not a fallback — it is the correct answer when the data is missing. The component should refuse to draw a band without both endpoints.

05 / Detail

The marker detail

Expansion in place, chosen on usability grounds rather than novelty — with one exception.

Why in place, not a drawer or a page

You keep your place

Function opens a right-hand drawer that covers the page. You gain the marker and lose the area you were reading. With six areas and ~34 markers, browsing is the main activity — context is worth more than focus here.

One implementation, two viewports

A drawer needs a different pattern on mobile (a sheet), which means two components, two focus traps, two sets of bugs. In-place expansion is identical at 1440 and 390.

Accessible by default

A native <details> element gives keyboard operation, screen-reader semantics and the browser's own find-in-page for free. Function's rows are plain buttons with no aria-expanded — a real gap on a medical site.

The exception: six pages

The signature marker in each area gets its own indexable URL, because someone googling "ferritin referenceområde" should land on a page. Six real pages, not thirty-four thin ones. Everything else deep-links to an expanded row via a hash.

06 / Layers

Layer 1 meets Layer 2

Three touchpoints, deliberately quiet, and one figure that explains the model once.

Touchpoint 1 — the area footer

A mono line under a rule at the end of each chapter: "Bag dette område — Pandonia-modellen". You have just read the markers; now you are told what connects them. Arriving after rather than before is the whole trick — it reads as an explanation, not a second taxonomy.

Touchpoint 2 — the marker detail

Two mono fields side by side: OMRÅDER and BIOLOGISK SYSTEM. A marker can list several of each, and that is where the many-to-many becomes visible without any diagram at all.

Touchpoint 3 — the model chapter

At the foot of the page, on deep forest: the six systems explained properly, once, with one figure. This is where a curious reader goes to "gå et niveau dybere". It is never in the navigation.

Why one figure and not six

The crossing-lines diagram appears exactly once on the whole site. Phase 2's "one orchestrated moment per page" logic applied to diagrams: a device used once is an explanation; used six times it becomes decoration.

The figure is half-empty on purpose

Left side verified, right side pending — and the figure says so. It will fill in when the mapping arrives, and until then it demonstrates the structure without asserting anything.

Layer 2 is never a link target

The six system names are set in mono, on a dark ground, in a chapter at the foot of the page. You cannot navigate by them. That single restriction is what keeps the two layers from competing.

Not forced into a tree

No breadcrumb reads "Hormoner › Signalering › TSH". The data model is a marker with two lists of memberships, and the UI never implies containment.

07 / Search

Search and discovery

A filter, not a search engine — with a stated threshold for when that changes.

The recommendation

One live filter field in the index bar. No search page, no modal, no results template. At roughly 34 markers across six areas, the entire page fits in a few screens; a full search experience would be more machinery than the content justifies.

Why a filter is still needed

Because people arrive with a word, not an area. Someone thinking "kolesterol" does not know it lives under Hjerte og kar — and under the two-layer model they are even less likely to guess. The filter is what makes Layer 1 navigation safe to commit to.

The threshold

If the marker count passes roughly 60, or if Hvad vi måler starts carrying article content, revisit. Until then the filter above is the whole feature — and it works in this prototype, so you can try it.

What it must match — a data requirement, not a UI one

Danish and English

"D-vitamin" and "vitamin D". "Kolesterol" and "cholesterol". The site is bilingual and Danes search in both.

Lay synonyms

"Langtidsblodsukker" must find HbA1c. "Stofskifte" must find TSH, T3 and T4. This is the single highest-value field in the whole data model and it is invisible — it needs a synonyms[] array per marker, written by someone who knows what Danes actually call things.

Panel names

"Lipidprofil" should find every marker inside the lipid panel, not one row called "Kolesterolprofil". Which requires knowing the panel contents — currently unpublished, and item 5 in the register.

Forgiving matching

Case- and diacritic-insensitive, substring, no fuzzy matching. "Vitamin" finds D-vitamin; "vitmain" finds nothing and says so plainly with two suggestions.

08 / Product

Connecting to the product

Two CTAs on the entire page. The rest of the connection is carried by information.

The inclusion column does the work

Every marker row says Health Test, or Health Test · også enkelttest. Reading the page, you are continuously told that these are the things Pandonia measures — without a single interruption. It is Function's included/add-on idea, stripped of the badge.

Where the two CTAs sit

One tertiary at the end of the opening (Se hvad et tjek koster →), and one primary at the very bottom after the limits section. Nothing between. A reader exploring their own biology should not be sold to every 600 pixels.

The individual-test link

Where a marker is also sold separately, the detail names the product and its price — D-vitamin Test · 1.000 kr. That is genuinely useful information, and it surfaces the seven products currently invisible on the site.

What we don't measure

A short closing section listing what the test does not cover. No competitor has this. It costs one paragraph, it prevents the most damaging kind of disappointment, and it is the strongest trust signal available on a page like this. Written by a clinician — item 14 in the register.

09 / Function

Function Health, compared

Read live again, including the marker drawer, which I had not opened before. Their detail experience is more specific — and more problematic — than I assumed.

What Function does exceptionally well

The pronunciation guide

Under "Ferritin" it prints fair-ih-tin. One line, almost free, and it transforms an intimidating word into something you can say out loud. The single best detail on the page, and we should take it — Danish markers like "homocystein" need it more than English ones do.

One paragraph that covers four questions

What it is, what low means, what high means, and what it usually calls for — in about 70 words, without subheadings. Tight, readable, and a better model than a long structured page.

Deep-linkable detail

Opening a marker writes #biomarker-ferritin to the URL. Shareable, bookmarkable, back-button-safe.

"Ignored by most. Tested by us."

Four unexpected markers before any list. Depth before volume, executed in one sentence.

What would be wrong for Pandonia

The "Possible conditions" chips

Ferritin's drawer lists ANEMIA · CHRONIC INFLAMMATION · HEMOCHROMATOSIS · IRON DEFICIENCY · LIVER DISEASE. A browsing consumer with no result meets five diseases attached to one marker. It is the fear register, and it contradicts everything we decided about not being alarmist. Our equivalent field — "hvad kan det pege på" — must be a sentence in careful language, never a list of diagnoses.

The drawer covers the page

You gain the marker and lose the category. With 160 markers that trade may be worth it; with 34 it is not.

A hard CTA inside the drawer

"Join Function to test" sits directly under the disease list. Curiosity → anxiety → purchase is an effective funnel and the wrong one for a Danish clinical brand.

No units, no ranges, anywhere

Function's What We Test page shows no reference range and no unit for any marker. Given 160 markers and a US audience that is defensible. For Pandonia it would waste the Nulpunkt language entirely — and it is the clearest opening to be better than the benchmark.

Buttons without state

Marker rows are plain <button> elements with no aria-expanded and a role="dialog" drawer. Native <details> gets us more, for less.

Where Pandonia can be simpler, more human, and clearer

Simpler: six areas against twenty-four categories. Function needs a search field and a sticky rail because its taxonomy is unmanageable. We need a 46px bar and a filter.

Structure

More human: Function's page has no photography inside the taxonomy at all — it is a cream list from the category rail to the footer. Every Pandonia area chapter opens with a photograph and a serif line, so the page breathes six times.

Rhythm

More human: our opening is one marker touching three concerns, in Pandonia's own words. Function's opening is four markers you didn't expect. Both are depth-before-volume — ours also teaches you how to read the page.

Framing

Clearer test → result → understanding: Function's chain ends at "Join Function to test". Ours ends at a named doctor who walks through the numbers. The inclusion column, the individual-test prices and the limits section all connect the science to the actual service rather than to a checkout.

Chain

Where they are still ahead: they have the content. 160 markers with a written paragraph each, live today. Our structure is better and our cupboard is empty — which is what the register in §11 is for.

10 / System

Proposed additions to the Phase 2 system

Seven. Six are additions the homepage never needed; one is a build rule.

  1. Band state: reference only, no value

    Phase 2 defined the band as range + value. On Hvad vi måler there is no value, so the band shows the interval alone. This is now the most-used state on the site and it needs a formal spec.

  2. Band state: no simple range

    A bare scale with a tick and no sage band, labelled INGEN ENKEL REFERENCE. Phase 2's two-state model assumed every marker has an interval. Ratios and context-dependent markers do not, and without this state the component would teach a false universal good/bad scale across the whole page.

  3. Band state: unavailable

    Diagonal hatch at 7% ink, em-dash endpoints, a mono reason. Covers pending data and unanalysable results.

  4. Band variant: stacked ranges

    Two or more bands with mono labels for sex or age. Stacked, never a toggle — a toggle hides that the ranges differ at all.

  5. Inclusion label

    Mono, 9px, +0.1em, ink-3, right-aligned. No fill, no border, no radius — so the Phase 2 ban on pills and chips stands. It is typeset metadata, not a badge.

  6. Fourth density: Expanded

    Phase 2 defined Air / Standard / Dense at section level. An opened marker row is a fourth, internal density: 8px rhythm, hairlines at 9% ink, inside a Standard section. Needed so expansion feels like opening a drawer in a cabinet rather than starting a new section.

  7. The .pl placeholder convention — and a build gate

    Dotted left rule, ink-3, red mono tag. Proposed as build-blocking: the production build fails if any element carrying .pl or .ptag reaches it. That converts "we'll remember to replace the placeholders" into something the pipeline enforces — which on a medical site is the difference between a convention and a safeguard.

No homepage change required. Phase 4 exposed nothing structural. One small coordination note: homepage beat 04 features vitamin D, and so does this page's opening. Rotate one of them — the homepage is the better place to rotate, since it already plans to cycle its featured marker.
