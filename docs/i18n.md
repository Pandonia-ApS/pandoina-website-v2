# Danish / English

Danish is the source of truth. English is a full locale, not a translation
layer. Nothing about the design, tokens, components or clinical gate changes.

---

## Route map

Both locales are prefixed. `/` is a single redirect to the negotiated locale.

| Key | `/da/…` | `/en/…` |
|---|---|---|
| `home` | `/da` | `/en` |
| `whatWeTest` | `/da/hvad-vi-maaler` | `/en/what-we-test` |
| `howItWorks` | `/da/saadan-fungerer-det` | `/en/how-it-works` |
| `yourReport` | `/da/din-rapport` | `/en/your-report` |
| `about` | `/da/om-pandonia` | `/en/about-pandonia` |
| `faq` | `/da/faq` | `/en/faq` |
| `book` | `/da/book` | `/en/book` |
| `business` | `/da/virksomheder` | `/en/for-business` |
| `privacy` | `/da/persondatapolitik` | `/en/privacy-policy` |
| `cookies` | `/da/cookiepolitik` | `/en/cookie-policy` |
| `terms` | `/da/handelsbetingelser` | `/en/terms` |
| `contact` | `/da/kontakt` | `/en/contact` |

Anchors are localised too, because they end up in shared links:
`#laboratoriet` / `#the-laboratory`, `#priser` / `#prices`, `#modellen` / `#the-model`.

### Why Danish is prefixed rather than left at the root

An unprefixed default (`/hvad-vi-maaler` beside `/en/what-we-test`) gives the
root two jobs — locale-neutral entry *and* the Danish homepage — and every
canonical, hreflang and middleware rule then needs a Danish special case. With
both prefixed the routes are symmetric and `/` is one redirect.

**Cost:** existing Danish URLs move. 301s are required at launch:

```
/                      → /da          (307, locale-negotiated)
/hvad-vi-maaler        → /da/hvad-vi-maaler        (301)
/saadan-fungerer-det   → /da/saadan-fungerer-det   (301)
…and the rest
```

If you would rather keep the current Danish URLs live, say so — it is a
middleware change, not a rebuild, but it brings the special-casing back.

## File structure

```
src/
  i18n/
    config.ts            locales, route map, href(), alternatePath()
  content/
    da/                  Danish editorial copy
    en/                  English editorial copy
    shared/              images, products, structural data — locale-neutral
  data/clinical/
    locale-types.ts      LocalisedClinicalField, SharedFact
    biomarkers.ts        universal data + per-locale copy on one record
```

**One website, two content sets.** Components, tokens, layout, images,
interactions, marker structures and validation are shared. Only strings differ.

### Biomarkers: universal vs locale

One record, never two databases.

```ts
{
  slug: 'd-vitamin',                    // universal
  unit: sharedFact({ value: 'nmol/L' }), // universal
  range: sharedFact({ … }),              // universal
  areas: […], systems: […],              // universal
  synonyms: { da: [...], en: [...] },    // locale — lay search terms differ
  name:    { da: 'D-vitamin', en: 'Vitamin D' },
  summary: daVerifiedEnPending({ … }),   // locale, separately gated
}
```

Reference ranges, units and category relationships are facts about the body and
the assay. They are declared once. Only the words differ.

## The clinical gate, per language

> **A verified Danish clinical statement is not a verified English one.**

Translating an approved sentence produces an unapproved sentence. `ClinicalField`
becomes `LocalisedClinicalField` with independent `da` and `en` status, plus a
`translation` status tracking the editorial lifecycle separately.

```ts
summary: daVerifiedEnPending({
  id: 'marker.d-vitamin.summary',
  daValue: 'Lavt D-vitamin er udbredt i Danmark, især i vinterhalvåret.',
  daSource: 'Pandonia booking system',
  enDraft:  'Low vitamin D is common in Denmark, particularly through the winter.',
  enNeeds:  'English wording needs clinical sign-off. Danish approval does not carry over.',
})
```

`blocksBuild()` returns true if **either** locale is unresolved. The validator
reports per locale:

```
  da  12 verified   19 pending
  en   4 verified   27 pending
  BUILD BLOCKED — 46 unresolved locale-fields
```

**Do not weaken this to ship English faster.** If the English site must launch
before clinical translation is complete, the correct move is to launch fewer
English pages, not lower the bar.

### Product facts are shared, not translated

`34`, `3.500`, `2–4 timer` are declared once as `SharedFact` and formatted per
locale (`3.500 kr.` / `DKK 3,500`). A number cannot drift between languages
because it exists in one place.

## SEO

- `<html lang>` — `da` / `en`
- **hreflang** on every page: `da-DK`, `en`, and `x-default` → `/da`
- **Canonical** — self-referencing per locale. No cross-locale canonicals.
- **Open Graph** — `og:locale` `da_DK` / `en_GB`, plus `og:locale:alternate`
- **Sitemap** — every route in both locales, each entry carrying its `alternates`
- **No medical structured data** in either language while clinical content is unverified. English FAQ schema is *more* dangerous than Danish: it is likelier to be surfaced as a featured snippet outside the market the disclaimer was written for.

Duplicate content is handled by hreflang plus self-canonicals. The two locales
are genuinely different text, not a machine mirror, which is the real defence.

## The language switcher

Two letters in the utility group — `DA · EN` — active one in forest with a 1px
underline. It does not become a dropdown.

It goes to **the equivalent page**, never the homepage:
`alternatePath('/da/hvad-vi-maaler', 'en')` → `/en/what-we-test`. Anchors are
carried across. Only a route with no counterpart falls back to the homepage.

- **Mobile:** both languages sit in the full-screen overlay at readable size —
  not hidden behind a third tap.
- **Memory:** the choice is stored in `localStorage` and read on `/`, wrapped in
  try/catch. First visit falls back to `Accept-Language`, then Danish.
- **Never** auto-redirect a visitor who has explicitly chosen a locale. A Dane
  reading the English site did that on purpose.

## English voice

Same rules as Danish: state, don't sell; a number instead of an adjective; say
the unglamorous thing; never promise an outcome.

British spelling — *analysed*, *programme* — for a Copenhagen company writing to
a European audience.

**Banned, same as Danish:** unlock your health · optimize your wellness · take
control of your health · your health journey · transform your health ·
revolutionary insights · best version of yourself.

Two translation traps specific to this brand:

1. **"Sundhedstjek" → "health check-up"** sounds like a GP appointment. Use
   *blood test* where that is what it is.
2. **"Prøve" is both sample and test.** Danish glides between them; English has
   to choose per sentence.

## Terminology that translation must not resolve

Two of the six Pandonia model labels were already flagged. English makes it
worse: **there are now two published English label sets and they disagree.**

| Danish | pandonia.com/en FAQ | Pandonia report UI |
|---|---|---|
| signalering | cellular signalling | Signaling |
| transport | transport | **Highway** |
| fordøjelse | digestion | Digestion |
| energi | energy production | Energy |
| immunforsvar | immune defence | **Defense** |
| affaldssystem | detoxification | **Waste** |

This is a product decision, not a translation one. The English labels stay
`requires_review` until Pandonia picks one set. **Do not resolve it by choosing
the nicer word.**

## Visual regression

English runs roughly 5–10% longer in body copy and slightly *shorter* in the
hero. Findings and the measurements are in the Phase 6.6 register. The rule:
**edit the English copy before touching the layout.** A global type reduction to
accommodate one long English sentence is not permitted.
